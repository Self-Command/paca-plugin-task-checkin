# Paca 双向任务同步、图片压缩与循环任务实施计划 v1.2

计划日期：2026年10月7日  
批准与实施日期：2026年10月8日  
状态：已批准，实施中。本版完整替代原图片压缩与循环任务计划。

## 1. 目标与确认范围

**Paca 页面／API／AI 创建任务 ⇄ 官方 TaskNotes 任务同步 → 服务器独立排期 → PushGo 提醒与拍照打卡 → 两端同步状态、记录和照片。**

任务同步不以打卡为前提。Paca 创建任务后，Obsidian 下一次自动或手动同步就创建对应 TaskNotes 笔记。

首次接入同步所选 Paca 项目的全部任务，包括已有、已完成和已归档任务。其他项目不受影响；TaskNotes 侧保留现有接入关系，未关联历史任务提供批量选择接入。

| 项目 | 本次职责 |
|---|---|
| A：TaskNotes Webhook 插件 | 双向任务接入与循环管理，保存关联、版本、变更日志及冲突 |
| B：PushGo 队列插件 | 按普通任务和每期任务安排提醒，保留可靠投递 |
| C：Paca 打卡插件 | 上传前压缩照片，管理打卡窗口、照片及状态更新 |
| D：Obsidian 打卡同步插件 | 升级为 Paca 任务同步，负责增删改、离线补交、记录和照片回写 |
| 官方 TaskNotes、Paca | 使用固定官方基线，不修改源码 |
| PushGo App、Gateway | 本轮无需修改 |

D 保留现有插件 ID、设置和数据，覆盖升级。四个插件独立发行，单人顺序开发，所有编译、lint、自动化测试和打包均走 GitHub Actions。

## 2. 双向任务同步设计

### 2.1 同步字段与内容边界

双向同步标题、任务内容、开始时间、结束时间、状态、优先级、标签、归档及循环规则。

- 状态与优先级采用项目配置的真实值映射，不硬编码名称。
- 精确时间、仅日期和未设置分别保存；仅日期不解释为午夜。
- Paca 描述与 TaskNotes 内容通过 Markdown／富文本转换。支持格式做往返验证；不能转换的内容保留原始数据并提示，不静默丢弃。
- 打卡区块、同步标记及打卡图片引用不作为普通内容反复上传。
- 保留未映射的 YAML 属性和用户附加笔记区块。
- 本期不扩展普通附件、评论、看板配置和 AI 聊天历史；打卡照片完整回写。
- TaskNotes 创建、修改、归档和周期操作使用官方公开 API。

### 2.2 服务器关联与变更日志

A 作为同步协调者，新增稳定 sync_id，关联 Paca 任务 ID、vault、路径及别名；保存 revision、双方已确认快照、操作 ID、字段变更、删除墓碑、持久 inbox／outbox、设备进度、回执和冲突。明确区分普通任务、循环母任务及周期任务。

迁移复用已有来源关联，不按标题合并。同名新任务视为不同任务，除非用户明确关联。

Paca 页面、API、AI 操作通过事件接入，每分钟官方 API 对账。仅完整扫描成功且单任务查询确认不存在才认定删除；网络、权限和分页异常不触发批量删除。核心任务走官方 API，每个插件只访问自己的 schema。

### 2.3 Obsidian 创建、修改与删除

统一流程：持久记录及补交本地操作 → 拉服务器变更并比较版本 → 创建或更新 TaskNotes → 回写记录和照片 → 验证实际结果，确认回执和进度。

- 创建：先持久保存意图并领取服务器租约，再调官方 API。结果不明进入核对，不盲重建。
- 修改：只提交明确改变的字段，不能顺带上传先前手改 MD 的时间。
- 删除：Paca 删除关联笔记默认进入 Obsidian 回收站；TaskNotes 界面删除同步删除 Paca。保留墓碑和打卡历史。
- 归档和取消归档双向同步，独立于删除。
- 改名／移动更新路径，ID 不变。
- 意外缺失标待关联、不自动恢复；明确删除才进入双向删除。
- 2026-10-08 已获用户确认：允许手改任务字段通过官方事件自动同步。官方事件不携带可靠的 UI／文件来源，因此不再承诺严格屏蔽 MD 修改。未触发官方事件的变化保留“Paca：提交当前任务更改”，预览差异后明确提交。
- 统一命令及设置按钮“Paca：同步任务、打卡记录和照片”。启动、恢复前台、定时及手动共用单一流程，默认 5 分钟，兼容桌面和移动端。

### 2.4 冲突、防循环与多设备

不同字段按共同确认快照合并；同字段保留两版让用户选择，不采用最后收到的覆盖。删除撞未提交修改时暂停删除。

操作携带 op_id、基础 revision；重复返回原结果，同 ID 不同内容拒绝。上下文辅助识别，结合预期字段、内容校验值和回执，不能只依赖 Webhook 的 source。

同 vault 电脑手机可使用同一配对凭据，设备游标与操作队列独立，关联共享。租约到期不自动允许重建，先核实原操作结果。

Paca API 与插件数据库不处于同一事务：字段级 PATCH、写前核对、写后验证、事件对账；并发竞争保留快照并进入冲突，不宣称跨系统原子提交。

### 2.5 配对与接口

A 新增 /task-sync/v1/：配对、增量、操作、绑定、回执、冲突、周期查询。worker 增加 HTTP 服务并使用数据库连接池。

Nginx 仅新增路径反代，沿用 HTTPS，无新增公网端口。现有 C 凭据通过受限内部接口授权迁移，D 自动保存 A 凭据且保留照片凭据。新安装一次配对获得权限，日常不反复密码。

A 普通同步独立运行，C 仅在打卡时参与。权限限项目、vault，不暴露服务账号和推送密钥。

## 3. 循环任务与图片压缩

### 3.1 循环统一排期

服务器 A 唯一协调；Paca、TaskNotes 均可编辑规则，但不能产生两套提醒。

- 使用固定官方版本对应 @tasknotes/model，锁依赖且对照官方输出。
- Paca 任务扩展提供规则、锚定、精确时间和下一期预览；A 增加调用者权限范围 MCP 工具，普通 AI 建任务沿用现有入口。
- 原六 Webhook 保留，新增 recurring.instance.completed、recurring.instance.skipped。
- 稳定 series ID＋官方 occurrence date 唯一关联；规则版本单独管理。
- 母任务保存规则、不直接提醒；每期独立任务、提醒、状态、打卡及照片。
- 固定周期未来 30 天、每分钟补齐、每系列每批最多 200；首次不批补过去提醒。
- 完成锚定只生下一期，完成后算后续；跳过遵循官方。
- TaskNotes 自生周期笔记关联已存在 Paca 期，不再重复创建。
- 区分循环起点和下一期 scheduled；完成推进不误判整条规则修改。
- 改规则调整未开始期，开放窗口冻结，改期明确冲突。
- 单期删除／跳过仅取消该期并存墓碑；删除母停止系列，归档暂停，取消归档只恢复未来。

D 拉期创建／关联笔记，无需先打卡。打卡早于首次 Obsidian 同步时，保留记录和媒体，建笔记后回写。

### 3.2 上传前压缩

- 校正方向，最长边 2048px，JPEG 初始质量 82%，目标 512KiB。
- 逐步降质量和尺寸，最低 65%、1024px，最终上限 1MiB。
- 小图不放大；合规且转换后更大保留原文件；透明 PNG 转 JPEG 用白底。
- 原文件 JPEG／PNG／WebP、10MiB、2500 万像素。
- 预览实际上传文件；失败明确提示，不静默上传大原图。
- 服务端仍校验真实格式、规范化、去 EXIF。
- 复用现有原生组件，生产 UI 全中文，无调试文字。

两卡独立、到点关闭、最终服务器提交时间判定；成功记录不覆盖；照片默认保留 90 天；附件默认独立 PushGo附件/。

## 4. Action 验收与发行

固定官方 Paca v0.18.6（6791ae2c8cc1a893b0c6799cf7d24df303e8e0b0）、TaskNotes 4.13.8 审查基线 69535cd956d11474b980deef8429ff0be232185f。实际官方发行资产、源码对应及校验沿用 Action fixture lock；四候选固定 SHA，不浮动组合。

| 类别 | 验收 |
|---|---|
| 双向 | 页面／API／AI 批量创建、两端改完恢复归档删除 |
| 首次 | 完整分页、关联、同名不同、完成归档导入，扫描失败不误删 |
| 幂等恢复 | 超时、丢响应、重启、创建中断、重复事件操作、防循环 |
| 冲突多端 | 不同／相同字段、删除撞修改、两端创建、离线补交、旧版本 |
| 正文媒体 | 格式往返、原始保留、托管区块排除、去重、区块被改、媒体重试 |
| 循环 | 日周月年、完成锚定、月末闰年、时区跨日、改规则、单期删除／跳过、母暂停 |
| 离线一天 | 服务器持续提醒；恢复每期唯一笔记、状态照片正确 |
| 压缩 | 方向、透明、损坏、限制、真实上传压缩文件、取消重选、跨截止 |
| 回归 | 原六事件、一次性、中文完整卡、四级、窗口、禁用 |

真实 Obsidian UI E2E 在 Action 隔离 vault；浏览器捕获实际上传；普通 AI 与循环 MCP 权限批量分别验收。发行插件包、D ZIP、SHA256、源码 SHA、双架构 worker digest。真机速度与相机用户验证，单独记录。

## 5. 顺序、部署与交付

1. 更新文档与验收清单，锁基线。
2. C 照片压缩 Action 通过先部署。
3. A 关联、日志、对账、配对、冲突接口。
4. D 普通双向，验收批量、增删改、多设备。
5. A 循环／Paca 扩展，B／C 每期提醒打卡。
6. D 周期笔记、离线补交，固定版本全链路。
7. 精确 digest 分阶段部署，先测试再启用所选项目全部同步。

备份 PostgreSQL、schema、配置、对象存储引用、镜像。增量迁移保留任务、配对、队列、打卡；开关默认关，齐版本后启用。首次任务清单预览确认基线后自动增量。

服务器由我配置，Obsidian 地址、配对、映射交付用户。沿用 /opt/paca-task-platform；保留 Gateway、WSS、Cabinet、证书、HMS 凭据。失败回退配套产物配置，不兼容变化恢复配套备份。

交付文档、四 Release、digest、安装配对、冲突、回滚与 Action／服务器／真机区分验收记录。

事实边界：收到离线规则修改前执行最后确认规则；已提交 Gateway 消息不可保证撤回，但旧打卡入口必须失效。
